测试用例编写需求的开发与测试方案调研评审

报告 ID：RES-TCD-DEVTEST-001｜日期：2026-07-16｜深度：standard｜状态：complete｜性质：调研输入，不修改总需求文档

结论：现有方案的治理方向是正确的，尤其是“不把 PRD 当作绝对真值”“RC 必须由用户确认”“变更先做影响候选、后做人工裁决”。下一步不应先接入大型框架，而应以可验证的结构化数据链为先：SRC/EVD/CLM → RC → MOD/OBJ/STATE → TP/TC → RUN/EVD → ISS/RCA，并为每一段加入模式校验、双向追溯、版本化回归集和可审计的发布门禁。建议按七个阶段建设，每阶段先完成自动化验证再进入下一阶段。

问题为“测试用例编写与治理”需求形成开发架构、测试策略和分阶段计划；评审现有参考资料和既有方案的缺陷与优化点。
输入依据当前《测试用例编写完整流程与需求文档 v2》、2026-07-15 的开源 Skill 调研评审、已确认的来源治理和 RC 决策。
不在本次范围不部署知识库、不安装第三方项目、不扫描其他磁盘、不访问私有系统、不写入总需求文档、不自动确认 RC。
关键授权边界用户统一提供来源并确认 RC 及新旧关系；Agent 只能提出 candidate、冲突和影响候选；正式用例只能引用适用且有效的 RC。

2. 研究发现与设计判断

发现证据与判断对本需求的落地要求
追溯必须双向且持续维护NASA 将需求到设计、代码、验证和不符合项的双向追溯作为生命周期活动，并指出无父项或无下游验证的孤立项必须被识别和处理。NASA SWE-052发布门禁同时检查“RC 无 TP/TC”“TC 无 RC”“执行失败无 ISS/RCA”“变更无 IMP”，而不是只统计用例数量。
变更要先评估影响，再裁决NASA 的变更管理要求在批准和实施前评估架构、接口、设计、代码、测试、成本和风险等影响。NASA SWE-053CHG 只登记新旧来源差异；IMP 是候选子图；只有用户确认关系后才更新 RC 或使正式用例失效/待回归。
来源、活动与责任人需要一并记录W3C PROV-O 以实体、活动、责任主体及派生/修订/失效关系描述可机读溯源。W3C PROV-O每一次导入、提取、人工确认、渲染和执行都保留输入版本、输出 ID、操作者或 Agent、时间和工具版本；不以“最后文本”覆盖历史。
模型化测试设计有收益也有盲区ISTQB 提出模型元素可增强测试条件追溯并支持多格式输出，同时警示自动化设计可能遗漏模型之外的测试条件、低估维护成本。ISTQB CTAL-TA v4.0统一 TC Model 生成 HTML/Markdown/JSON，但保留“模型外探索项”和人工审查采样；渲染结果不可作为独立编辑源。
UI 成功不是业务成功Playwright 可监听请求/响应并等待目标响应，断言会重试直到满足条件或超时；Trace Viewer 可回放 DOM、网络和动作。网络验证、断言、追踪实践测试预言机分为 UI、接口契约、状态机、异步任务、下游业务和恢复安全六类。提交、Toast 或跳转只可证明 UI 层，不能单独关闭业务验证。
Agent 本身要持续 TEVVNIST 将可重复的测试、评估、验证和确认（TEVV）置于 AI 生命周期；OWASP 要求对检索内容、记忆、工具调用和高影响操作进行输入验证、最小权限、人工监督和对抗测试。NIST AI RMF 1.0、OWASP AI Agent Security建立版本化黄金回归集、拒绝/不确定集、注入样本和结构契约测试；检索命中、模型置信度或自评都不能替代 RC 与确定性验证。
服务间验证需要独立契约层Pact 的 Provider Verification 由消费者定义其对提供者的假设，并在提供者端验证。Pact Provider Verification当测试用例涉及 API 或下游时，加入请求/响应结构、错误语义、幂等和异步终态的契约测试；不把浏览器录制当作接口契约。

3. 对既有资料与方案的缺陷评审

下表不否定既有结论。前一轮资料已正确识别“PRD 真值假设、覆盖不可验证、文本匹配式增量、预言机薄弱、根因闭环不足”等核心风险；本轮补足的是把这些原则变成可开发、可测试、可发布的工程控制。

缺口风险优化点验收方式
对象虽已定义，缺少可演进的数据契约字段含义漂移、旧数据迁移猜测、不同输出不一致。为每个对象定义 JSON Schema、schema_version、稳定 ID、不可变审计字段和显式迁移表；禁止按同名字段推断迁移。schema 单测、旧版样本迁移测试、反向兼容或明确拒绝测试。
RC 人工确认已明确，裁决工作流尚未产品化候选主张被误升格，或确认范围无法复现。RC 记录必须包含确认人、确认时间、适用知识空间/版本/环境、来源主张、关系类型和失效条件；状态机只允许受控迁移。无确认人或范围的 RC 被拒绝；candidate 不能进入 formal TC 的负向测试。
影响分析只有原则，缺少“语义差异”判定层仅凭关键词造成漏回归或过度回归。CHG 保存段落/字段级差异与人工语义标签（对象、状态、角色、约束、接口、下游）；IMP 以图遍历产生候选并要求人工处置。同义改写、状态迁移变化、权限变化、接口字段变化四类金样本；测量漏报和误报。
覆盖指标没有明确分母、分层和阻断阈值“覆盖率高”但关键 RC、风险或预言机没有覆盖。分别计算有效 RC 覆盖、风险覆盖、预言机覆盖、执行证据覆盖、孤立率；P0 RC 采用逐条门禁，其他阈值从基线校准，不预设虚假精确数字。构造缺失 RC/TP/TC/RUN 链路的负向数据集；报表必须定位缺口 ID。
环境、测试数据与清理契约不完整用例不可重复，或测试写入污染共享环境。定义环境能力清单、专用测试账号的授权流程、合成数据/夹具、数据生命周期、清理/恢复和幂等策略；生产数据默认不入库。并发重复运行、失败重试、清理失败、脱敏扫描和跨环境隔离测试。
Agent 质量评估尚未形成发布基线提示词、模型或检索变更悄悄降低事实性和稳定性。建立四类黄金集：追溯、冲突/不确定、变更影响、测试预言机；另建注入与敏感数据拒绝集。生成者与评审者尽量分离，人工抽样校准。每次变更比较结构正确性、事实支持率、人工一致率、拒绝正确率、耗时和成本；超出基线即阻断或降级。
执行证据未规定最小充分集截图或 Toast 被当成全链路通过证据。按预言机类型规定最小证据：UI 需截图/DOM；接口需请求响应摘要；异步需终态和关联 ID；下游需可定位的业务结果；失败需 Trace/日志指针和 RCA。刻意制造“UI 成功但 API/任务失败”的样本，验证不能误报通过。
安全边界有原则，缺少可测的拒绝行为外部文档可注入指令，敏感信息进入检索、日志或输出。来源内容一律视为数据；设置允许目录、文件类型、大小、脱敏规则、隔离命名空间、保留期、删除流程和工具最小权限。提示注入、含 Token 的 .env、真实个人信息、超大文件、越界路径五类拒绝测试，并验证日志无泄露。

4. 推荐开发架构与发布门禁

建议采用“结构化核心 + 可替换 Agent/渲染器 + 确定性验证”的架构。知识库检索和大模型用于发现候选、归类和提出问题；规则确认、状态迁移、模式校验、追溯校验、差异计算和发布门禁使用确定性程序。这样未来替换 RAG、模型或 UI 执行器不会改变已确认事实和正式用例。
层职责不可省略的控制测试重点
来源与证据层SRC、EVD、CLM 的登记、哈希、定位、版本和数据分级。用户指定来源；只增不改的版本记录；内容与指令隔离。重复导入、篡改检测、定位失效、脱敏与拒绝。
治理与裁决层ISS、Grill、RC、关系和状态机。仅用户可确认 RC；关系由用户确认；P0 未关闭禁止 formal。状态迁移、权限、冲突阻断、审计完整性。
领域与追溯层MOD/OBJ/STATE、TP、TC、CHG、IMP 的图关系。稳定 ID；双向链接；孤立项和循环链接检查。图完整性、变更影响、范围过滤、回归选择。
生成与渲染层统一 TC Model 生成 JSON、Markdown、HTML、执行交接包。单一事实源；输出只读渲染；模板版本可追溯。快照、跨格式等价、字段遗漏、确定性排序。
执行与证据层UI 探索、Playwright 确定性验证、网络/任务/下游证据、RUN、RCA。预言机分类；风险操作保护；失败不伪称通过。单元、契约、集成、E2E、恢复、证据完整性。
评估与安全层黄金集、对抗样本、质量指标、数据和工具策略。变更回归；最小权限；预算/重试/链深限制；人工抽检。事实性、拒绝、注入、泄露、稳定性、成本和延迟。

5. 分阶段开发与测试计划

阶段开发交付测试计划退出门禁
P0：范围与基线冻结术语、对象清单、ID 规则、状态机、角色权限、数据分级、目录边界与 ADR；建立样本项目和非敏感合成资料。术语冲突审查；角色授权矩阵；目录越界、敏感文件、未经授权来源的拒绝测试；手工走通“candidate 不能成为 RC”。用户确认 RC 的唯一授权边界；P0 负向用例全部通过；无真实凭据或生产数据进入样本集。
P1：结构化核心实现所有核心对象 Schema、稳定 ID 生成、版本/哈希、审计事件、显式迁移框架、图存储或关系存储接口。单元：Schema、ID、状态机、哈希；属性测试：重复导入幂等；迁移：旧版成功、未知版明确拒绝；图校验：孤立项/循环/重复链接。100% 核心对象通过 Schema；审计链可从任一 TC 回溯至 RC、EVD、SRC；迁移无字段猜测。
P2：导入、检索与挖掘用户显式导入、证据分段、CLM 提取、按知识空间检索的 Evidence Packet、Uncertain/Conflict/Need-review 状态。集成：版本、范围、冲突和引用均返回；对照集：相关/不相关/过期/冲突来源；安全：提示注入文本只作为证据、不改变流程。每条 CLM 可定位；检索无命中时明确 unknown；没有 RC 的结果不得生成 formal TC。
P3：Grill、确认与领域模型问题队列、Grill 问答、人工 RC 登记、关系确认、MOD/OBJ/STATE 建模和可视化追溯矩阵。状态迁移与审批测试；P0 阻断；关系集合白名单；同一规则在不同知识空间/环境中的范围隔离；人工审查样本回放。所有 formal 范围内 RC 都有确认人、适用范围和来源；未关闭 P0 为零；模型项与 RC 双向可达。
P4：测试设计与多格式输出TP/TC 生成、预言机分类、风险标签、数据/清理要求、自动化候选评分、统一 JSON 到 HTML/Markdown 渲染器。组合测试：正常、异常、边界、权限、状态、异步、恢复；渲染快照；跨格式 ID/数量/字段等价；正式/候选隔离；人工抽样评审。正式 TC 100% 链接到适用 RC；无孤立 TP/TC；三种输出差异为零；每个关键 RC 有可观察预言机。
P5：变更与回归选择CHG 差异、语义标签、IMP 候选图、人工处置、用例失效/待回归/保留状态和回归包。金样本：文字改写、规则变化、权限变化、状态迁移、接口契约变化；比对漏报/误报；验证不能自动覆盖 RC 或删除 TC。影响输出可解释到差异和路径；高风险影响均有人工处置；回归包可重复生成。
P6：执行交接与证据闭环Execution Contract、Playwright/Hybrid 交接、网络和异步证据捕获、RUN/ISS/RCA、重复根因升级。分层测试：单元、API 契约、集成、E2E；故障注入：UI 成功/API 失败、任务超时、下游失败、清理失败；Trace 和证据最小集检查。通过结论均有匹配预言机证据；失败均能定位到阶段和对象；同 RCA 第二次出现触发治理升级。
P7：Agent 评估与试运行黄金集、提示/模型/检索版本记录、对抗集、质量看板、预算限制、人工抽检和发布记录。回归：事实支持、结构合法、计划遵循、工具参数、拒绝正确、反谄媚；安全：注入、记忆污染、越权、数据泄露；性能：P50/P95、成本、重试与链深。相对已批准基线无未解释退化；安全拒绝集全过；人工抽检达到预先确认的阈值；试运行仅使用隔离环境与合成数据。

6. 测试策略与最小测试资产

测试层目标最小资产自动化位置
Schema / 单元对象、ID、状态机、渲染和评分的确定性正确。正常、边界、非法状态、未知版本、重复 ID、循环图样本。每次提交。
契约导入/检索/渲染/执行接口以及下游 API 的结构与错误语义稳定。JSON Schema、请求响应夹具、provider/consumer 合约、幂等样本。每次提交及依赖升级。
集成跨层追溯、影响分析、权限和审计联动正确。小型合成项目：冲突来源、确认 RC、状态机、异步任务和变更版本。每次合并。
E2E / UI用户从导入到正式用例与执行交接的关键路径可完成。隔离环境、可重置数据、稳定选择器、Trace、网络/任务证据。合并前冒烟；夜间全量。
黄金回归Agent 在事实性、冲突处理、覆盖和输出稳定性上不退化。标注期望、允许不确定答案、反例和人工裁决记录的版本化数据集。提示、模型、检索、工具或策略变更前后。
安全与隐私来源注入、越权读取、敏感数据持久化/输出和资源耗尽被阻断。恶意文档、伪造指令、.env/Token 模式、路径越界、超大输入、递归工具调用样本。合并前安全门禁与每次策略变更。
韧性与恢复失败重试、幂等、部分写入、渲染失败和执行中断可控可诊断。故障注入脚本、断点恢复夹具、清理/回滚检查表。发布候选与重大架构变更。

建议的发布判定

采用“硬门禁 + 趋势指标”而不是一次性强制排名。硬门禁包括：Schema 合法、无未关闭 P0、formal TC 有适用 RC、关键链路无孤立项、必需证据存在、安全拒绝通过、无未解释黄金集退化。趋势指标包括追溯完整率、影响分析误报/漏报、人工复核一致率、证据完整率、执行稳定性、耗时和成本。阈值应在 P0-P2 的合成基线上由用户确认，随后按版本比较；它们不应成为自动确认 RC 的替代品。

7. 优先级、依赖与待确认决策

优先级必须先做原因
P0对象 Schema、审计与状态机；RC 授权控制；追溯/孤立项校验；合成黄金集；敏感数据与目录边界。这是“可相信、可回滚、可测试”的地基，缺失时后续生成和 UI 自动化只会放大不确定性。
P1Evidence Packet、Grill 工作流、领域模型、统一 TC Model、多格式渲染、CHG/IMP。形成从来源到正式用例、再到增量回归的完整设计闭环。
P2UI/Playwright 执行交接、契约测试、执行证据与 RCA、评估看板。把“设计正确”扩展为“可重复验证”，并避免 UI 假阳性。
P3第三方评测/执行框架的隔离 POC 和 A/B 对照。只有已有基线、黄金集和安全边界后，才能客观比较 Promptfoo、DeepEval、Midscene、Explorbot 等工具的增益。
需在进入开发前确认的四项：1）第一个试点的项目/产品边界和知识空间命名；2）RC 确认与变更关系的记录载体；3）合成测试数据与隔离环境的可用性；4）P0 门禁和黄金集人工复核的负责人。若这些尚未确定，可先完成 P0 的数据契约和离线合成样本，不接入真实资料。

8. 证据质量、冲突与限制

  • NASA、W3C、ISTQB、NIST、OWASP、Playwright 和 Pact 是针对不同主张选择的原始或官方资料；它们共同支持原则，但不直接规定本项目的字段名、阈值或技术选型。
  • NASA 的要求来自高保证软件环境，因此本报告借鉴其追溯和变更方法，不把其安全关键覆盖目标机械套用到一般业务系统。
  • NIST AI RMF 1.0 的资源页提示框架正在修订；本报告固定引用 1.0 PDF，并将其作为 TEVV 和治理方法而非合规认证结论。

9. 主工作流建议
