1. 需求总结与完善

需求点完善后的定义开发含义
本地数据库D:\RAG 是受控本地知识库数据层，保存用户提供且通过准入的来源、证据、RC、状态、索引和下游交接产物。先实现目录、schema、manifest、frontmatter、证据 JSON、审计和文件索引；不先上向量库。
rag-system Skillrag-system 是根协调 Skill，不是一个巨大万能 Skill。它负责路由、门禁、上下文加载、子 Skill 调度和最终 Evidence Packet 输出。先设计根 Skill 的触发、输入、输出、安全边界和子 Skill 契约；真实 Skill 文件待后续授权创建。
子 Skill 拆分下属可拆为摄取、schema、治理、查询、变更影响、下游交接、评测等小 Skill。每个子 Skill 保持单一职责，长 schema 和示例放 references，重复校验逻辑放 scripts。
服务上下游上游接收 PRD、设计、接口、截图、日志、用户确认；下游服务测试用例编写、UI 自动化测试、Solution D、回归和交接。输出只读 Evidence Packet、RC Packet、Change Impact Packet、Test Asset Manifest、Solution D Evidence Contract。
安全与治理只读取用户清单内文件；敏感材料拒绝；confirmed_active 才能作为正式 RC；检索命中不是事实。所有 Skill 必须内置人工确认、阻断状态和敏感拒绝规则。

2. 总体架构

架构分两层：下层是本地数据库/知识库数据层，上层是 rag-system Skill 编排层。数据层保证“资料可信、可追溯、可审计”；Skill 层保证“Agent 读取方式受控、输出格式稳定、下游可消费”。

层模块职责事实源地位
数据层00_inbox 到 07_handover来源、证据、结构化单元、RC、冲突、变更、测试资产、交接。事实与审计依据。
缓存层08_cacheMVP 仅策略占位；达到阈值后接 SQLite FTS5；向量索引更后。非事实源，可删除重建。
根 Skillrag-system理解用户请求，检查边界，选择子 Skill，聚合结果，输出给下游。不创造 RC，只编排。
子 Skillrag-intake 等执行单一职责流程，如准入、查询、治理、下游交接。只能生成候选、报告或只读包。

3. rag-system 根 Skill 设计

建议名称rag-system
触发描述当用户要求使用本地知识库、RAG、本地证据库、知识入库、知识检索、RC 查询、为测试用例或 UI 自动化准备知识上下文时使用。
核心职责任务路由、知识空间检查、材料清单边界检查、状态机门禁、子 Skill 调度、Evidence Packet 聚合、下游交接。
禁止职责不自动扫描磁盘、不保存敏感材料、不自动创建 RC、不直接执行 UI 测试、不自动生成正式用例、不绕过用户审批。
最小输入用户请求、knowledge_space_id、允许材料清单或查询意图、目标下游类型。
最小输出Evidence Packet、阻断原因、待用户确认项、下游 handoff target。

6. 分阶段开发计划

阶段目标任务验收不做
PH-RAG-0开发基线冻结确认 PRD、space 规则、材料清单模板、根 Skill 与子 Skill 边界。开发 DoR 通过；P0 安全边界清晰。不写 D:\RAG。
PH-RAG-1数据层骨架设计产出目录、schema、manifest、示例 frontmatter、证据 JSON 模板。HTML/JSON/schema 校验通过。不导入真实资料。
PH-RAG-2根 Skill 设计设计 rag-system/SKILL.md 内容、触发描述、工作流、子 Skill 路由、拒绝规则。Skill 质量 rubric 通过；无额外 YAML 字段。不实际安装 Skill。
PH-RAG-3子 Skill 契约设计为 MVP 子 Skill 设计输入输出、references、scripts、assets 需求。每个子 Skill 单一职责；输出可验证。不创建冗余 README/教程。
PH-RAG-4MVP 端到端流程用合成样例串联 intake → schema → governance → query → downstream handoff。无 RC 阻断、active 阻断、confirmed_active 正向通过。不使用真实敏感材料。
PH-RAG-5下游适配为测试用例生成和 UI 自动化输出 handoff 契约。Test Asset Manifest 和 Solution D Evidence Contract 可被只读消费。不执行浏览器或生成正式用例。
PH-RAG-6评测与回归用户提供 PRD 等资料，Codex 生成黄金查询候选，用户审批后建立基线。黄金查询、拒绝集、跨 space、变更影响测试通过。不让 Agent 自批黄金集。
PH-RAG-7检索升级候选当语料规模、黄金查询失败率或人工查找成本达到阈值后，评估 SQLite FTS5。FTS5 POC 可重建、一致性可验；向量索引另行审批。MVP 不上向量索引。

7. 上下游服务契约

上下游rag-system 提供阻断条件
PRD/参考资料输入材料准入报告、来源登记、证据片段、知识单元候选。缺少用户清单、space 元数据不一致、含敏感信息。
测试用例编写Evidence Packet、RC Packet、Test Asset Manifest、oracle type、payload baseline 引用。无 confirmed_active、冲突未裁决、active 未批清。
UI 自动化测试页面/接口/证据引用、业务 ID 字段、失败归因字段、Solution D Evidence Contract。只有视觉证据、缺少 API/task/downstream 证据、环境超出测试范围。
Solution Dtrace、api、task、downstream、business_id、verdict、attribution 字段。内部实现未提供时只输出契约草案，不登记接口 RC。
回归维护Change Impact Packet、受影响 RC/用例/自动化资产列表。新来源未确认、旧 RC 被误改、变更影响无证据。
