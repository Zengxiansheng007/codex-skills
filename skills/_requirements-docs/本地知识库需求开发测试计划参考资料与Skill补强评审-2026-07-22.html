Key Findings

KF-02 开发计划中的跨 Skill 协作、契约、语义校验不能假设宿主天然支持。 P1 补强 Open Agent Skills Specification、JSON Schema 2020-12、Validation Vocabulary、Codex 本地 Skill 规则。 闭环。开发计划必须保留 Host Capability Report、Run Manifest、Handoff Contract、semantic validator。
KF-03 测试计划中 UI 可见、LLM 评分、工具评测都不能替代业务预言机。 P1 补强 ISTQB CTAL-TA v4.0、Playwright Best Practices、Playwright Tracing、DeepEval Tool Correctness。 闭环。UI/LLM 证据只作分层证据，正式通过仍需业务预言机和确定性证据链。
KF-04 安全与人工门控不能只由方案自定义，需要可复核安全资料支撑。 P1 补强 OWASP AI Agent Security、OWASP LLM Top 10、NIST SSDF 1.1、NIST AI 600-1。 闭环。禁入、待审、人工确认、对抗测试和证据保留均有高置信支撑。
KF-05 qa-skill、test-case-xlsx-generator、Solution D 的具体实现未由用户提供，不能作为当前 RC 或实现依赖。 P1 补强类比资料：OWASP HITL、SpecSmith、Promptfoo、DeepEval、Playwright、Pact、Explorbot/Midscene 官方资料；同时明确“具体实现待用户提供”。 闭环为实施前门禁，不再作为设计 P1 缺陷。

Evidence Table

E01W3C PROV-O需求W3C 推荐标准，适合支撑来源、责任主体、派生关系。完整 OWL/RDF 对本项目过重。只吸收 Entity/Activity/Agent、derived/revision/invalidation 最小子集。
E02JSON Schema 2020-12 / Validation Vocabulary开发正式结构化契约规范，适合 Agent-ready JSON/YAML。只能验证结构，不能证明语义、权限、RC 用户确认或链路完整。Schema + semantic validator 双门禁。
E03SQLite FTS5开发官方本地全文检索资料，支持 BM25、tokenizer、索引维护。中文分词、规模、性能需用首批语料验证。作为后置索引候选，不作为 MVP 前置。
E04OWASP AI Agent Security需求/开发/测试明确人类审批、最小权限、结构化日志、对抗测试、拒绝集。需要转化为项目字段、门禁和测试夹具。支撑人工门控、安全拒绝集和审计。
E05OWASP LLM Top 10需求/测试覆盖提示注入、敏感信息泄露、供应链、过度自治、向量/嵌入弱点。是风险分类，不是实现方案。转化为禁入、注入、越权、向量后置的负向测试。
E06NIST AI 600-1测试适合支撑 AI 系统 TEVV、记录、监控和生命周期治理。不给本项目阈值。用于 Evaluation Record、黄金集、拒绝集，阈值由用户语料和试点确定。
E07NIST SSDF 1.1开发安全开发框架，强调 SDLC 中记录安全要求、风险、设计决策和组件来源。不是 Agent Skill 专属规范。支撑开发计划的安全门禁、组件/依赖和变更记录。
E08NASA SWE-052 / SWE-053需求/测试双向追溯、客观证据、变更影响分析很适合 RTM 与 CHG/IMP。高保证环境较重。采用方法，不宣称 NASA 合规。
E09ISTQB CTAL-TA v4.0测试支撑测试依据、预言机、测试数据、环境、风险和回归。不覆盖 Agent 来源治理。用于测试计划和 oracle taxonomy。
E10Playwright Best Practices / Tracing测试官方资料，支持 trace、DOM 快照、网络请求和断言证据。浏览器层证据不能证明下游业务成功。作为 UI/API 证据链一层，必须配业务 ID/下游验证。
E11Promptfoo Assertions / LLM as Judge测试/参考 Skill支持 factuality、llm-rubric、JSON、相似度、RAG faithfulness、CI。LLM judge 有偏差，需校准；可能引入模型和依赖。P2 POC；不确认 RC 或业务成功。
E12DeepEval Tool Correctness / Agent Metrics测试/参考 Skill工具正确性有确定性部分，计划遵循、任务完成、trace 适合 Agent 评测。部分指标仍依赖 LLM judge，未本地复现。P2 POC；先用自有黄金夹具和确定性校验。
E13Midscene.js / Introduction测试/参考 Skill视觉驱动，适合页面探索、canvas、跨平台界面。截图可见不能证明业务成功。仅作探索素材，不能单独进入黄金集。
E14SpecSmith开发/测试/参考 SkillYAML-first、sync、validate --strict、孤立项、重复 ID、覆盖校验。治理体系偏重，不能直接替代本地知识库。吸收门禁思想，不安装执行。
E15Pact Docs / Verifying Pacts开发/测试消费者/提供者契约和 provider verification 思想成熟。服务 API 框架对文件型 Agent artifact 过重。吸收 contract-by-example 思想，使用轻量 fixture + schema + semantic validator。
