Key Findings

ID发现结论证据
KF-01 Markdown / GFM 规范明确把文档看成 block + inline 结构；GitHub 还明确支持表格和相对链接 / 图片路径。 支持把 md 作为第一版正文 canonical 格式，并将表格、列表、图片引用作为可保真的结构单元。 CommonMark 0.31.2，GitHub Docs tables / README relative links。
KF-02 python-docx 把段落、表格、inline picture / shape 当作可遍历对象；Word 文档天然有 text layer 和 drawing layer。 支持 doc/docx 的结构化抽取，但图片应按位置和引用保留，不把图片里的业务规则当作自动真值。 python-docx tables / shapes / API basics。
KF-03 pypdf 与 pdfplumber 都能做文本 / 表格抽取，但 pdfplumber 明确更适合 machine-generated PDF；OCRmyPDF 明确指出 scanned PDF 需要 OCR text layer 才可搜索。 支持“文本层 PDF 可处理、扫描件 / 图片型 PDF 先阻断”的硬门槛。 pypdf extract-text，pdfplumber README，OCRmyPDF docs。
KF-04 Open Agent Skills spec 和本地 create-agent-skill 都强调：SKILL.md 要短、可 progressive disclosure，细节放 references/。 新 skill 应是小型操作手册，不是长 PRD；详细块规则、fixtures、校验表都应下沉到 references。 Open Agent Skills Specification，create-agent-skill。
KF-05 本地 rag-intake、rag-schema、rag-governance、rag-downstream-handoff 已明确 candidate / confirmed_active 边界。 结构保真 skill 的职责是上游结构化，不是治理结论，不是下游执行。 本地 rag-* skills。

Main Workflow Recommendation

  1. 将新 skill 定名为 rag-structure-fidelity，归入 rag-system 子技能体系。
  2. 第一版只做结构保真，不做治理裁决：输入是 md 正文 + 语雀 / .lakebook 目录参照 + doc/docx/pdf 的原始来源清单。
  3. 输出只允许：结构化 Markdown、frontmatter、structure map JSON、evidence JSON、admission/reject report、validation report。
  4. 任何关键规则块丢失、扫描件 / 图片型 PDF、无法复原的表格 / 列表 / 图片占位，全部 blocked-structure-loss。
  5. 自动候选映射可以有，但只进 candidate / need-review，不得自动进 RC，不得直接给 downstream 作为正式真值。
  6. 实际安装到 .codex/skills 与真正执行写入 D:/RAG 仍是后续授权步骤，不应和本次设计结论混在一起。
