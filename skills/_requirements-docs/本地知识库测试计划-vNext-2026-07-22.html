本地知识库测试计划 vNext

documentType：Test Plan

测试目标：验证本地知识库 MVP 是否能安全摄取用户材料、保持知识空间隔离、区分证据与 RC、阻断未确认事实、向下游 Agent 输出可追溯证据包。

测试边界：本计划定义测试策略和验收项，不执行真实入库、不访问生产环境、不测试未提供的内部 Skill 实现。

1. 测试范围

范围内目录/schema、准入门禁、敏感拒绝、状态机、RC 用户确认、space 隔离、Evidence Packet、Change Impact、下游契约、索引重建。
范围外真实生产数据测试、账号登录测试、自动扫描磁盘、第三方 Skill 安装执行、完整 UI 自动化运行、SQLite FTS5 正式接入测试、向量库效果评测。
测试依据本地知识库 PRD vNext、开发计划 vNext、WorkBuddy PRD、Codex 历史 PRD、research 补强资料、Grill 决策。

2. 入场、暂停、退出标准

类别标准
Entry用户提供首个 knowledge_space_id、首批脱敏材料清单、黄金查询意图、允许文件类型；空库骨架与 schema 已生成。
Pause发现疑似凭据、访问令牌、Cookie、未脱敏生产数据；space 不明确；RC 规则冲突；测试环境将触达非测试系统。
Resume用户确认材料处理方式或提供脱敏替代；space 和 RC 范围明确；拒绝报告已生成且未复制敏感正文。
ExitP0/P1 测试全通过；无敏感误入库；无跨 space 召回；active 不可正式引用；报告证据完整。

3. Q7 展开：黄金查询与负向安全用例

黄金查询不是普通搜索样例，而是验收“知识库能不能被 Agent 安全使用”的最小基准。用户已确认：用户提供 PRD 等参考资料，Codex 基于这些资料生成黄金查询、负向安全用例和候选预期结果，再由用户审批后使用。它必须同时覆盖正确答案、阻断、隔离、敏感拒绝、变更影响和下游证据契约。

类别用户需提供Codex 补充预期结果
正确 RC 与引用业务代表问题、期望 RC、适用范围Evidence Packet 校验、引用回链返回 confirmed_active RC、来源、证据、定位。
无 RC 阻断尚未确认或待审问题状态机用例返回 need-review，不得生成正式用例。
冲突阻断两个版本/材料矛盾的例子CONFLICT 和 RC 审计检查进入 uncertain，等待用户裁决。
跨空间隔离两个不同项目/产品中同名概念space 硬过滤测试不得召回其他 knowledge_space_id 内容。
敏感资料拒绝脱敏后的模拟敏感样本类型拒绝集和报告校验拒绝入库，不写索引，不回显完整敏感值。
来源变化不改写 RC同一材料的新旧版本CHG/IMP 校验新建版本和影响候选，既有 RC 不自动变更。
下游契约一个可生成测试资产的真实业务问题Manifest 和 Solution D Contract 校验只有 RC 满足时生成只读下游输入。

为什么需要你提供：Codex 可以设计结构性、安全性和边界类用例，但不能替你定义“哪些业务问题最能代表真实工作”。如果黄金查询全由 Agent 编，测试会变成自证循环。

已确认流程：你提供 PRD、设计说明、接口说明、历史用例或其他参考资料；Codex 从中生成候选黄金查询、负向用例、预期 Evidence Packet 和阻断条件；你审批通过后，这些内容才进入正式测试基线。

6. 测试数据策略

  • 使用用户提供的脱敏材料和 Codex 构造的合成负向样本。
  • 敏感拒绝样本只使用占位形态，不记录真实密钥、真实 Cookie、真实客户信息。
  • 至少准备两个 knowledge_space_id 的合成空间，用于隔离测试。
  • 准备一组 old/new 来源样本，用于变更影响测试。
  • 准备 active、confirmed_active、uncertain 三类状态样本，用于下游门禁测试。

7. 缺陷分级与处理

级别定义处理
P0敏感信息入库、跨 space 召回、active 被正式引用、Agent 自动 RC、无证据正式答案立即停止测试，修复后全量回归。
P1证据回链不完整、状态机边界不清、变更影响漏报、下游契约字段缺失阻塞 MVP 验收，修复并重测相关链路。
P2报告可读性、命名、性能阈值、维护便利性问题记录并排期，不阻塞安全 MVP。

8. 回归策略

每次 schema、状态机、准入规则、RC 规则、查询契约、下游接口字段变化后，必须回归：结构校验、敏感拒绝、space 隔离、active 阻断、confirmed_active 正向查询、变更不改 RC、缓存重建、下游契约。
