入库产物结构与下游消费契约研究报告

生成时间：2026-07-26；研究深度：standard；模式：skill-design / plan-support。

结论：建议把“结构化入库 Skill”的产物设计成 一份候选材料包 + 一套可选下游只读包。第一版以 Markdown 为核心格式，语雀/lakebook 只作为目录分级来源和备用参考；Skill 只生成结构化入库产物和候选证据，不更新 RC、不替用户裁决。

推荐状态：caveated。没有 P0/P1 证据缺口，但完整字段名、验证脚本和未来 Skill 名称属于本地实现约定，需要在开发阶段用 fixtures 与 rag-schema 固化。

Scope And Assumptions

  • 研究问题：入库后的知识如何形成稳定、可追溯、可验证、可被 auto-testcase-generator、ui-test、Solution D 和通用 Agent 消费的产物结构。
  • 范围内：入库产物目录、字段分层、状态门禁、证据包、RC 包、变更影响包、测试资产清单、Solution D 证据契约、相关 Skill 分工。
  • 范围外：不执行真实入库、不写 D:/RAG、不创建或修改真实 Skill、不生成正式 RC、不执行下游测试或用例生成。
  • 已确认约束：Markdown 为核心格式；语雀/lakebook 作为目录分级来源和备用；结构保真优先，宁可阻断；关键规则区块无法复原则 blocked-structure-loss；只生成候选证据，不自动进入 RC；必须放在 rag-intake 之后。

Key Findings

  1. 下游消费不能直接读 raw 或普通 chunk。下游需要先拿到带来源、状态、范围、阻断原因和证据回链的 Evidence Packet；否则会重复出现“规则读取不全但答案看似确定”的问题。
  2. 完整入库产物应分成四层。源材料层、结构化知识层、证据/治理层、下游 handoff 层。缓存和检索索引只能作为可重建派生层，不作为事实源。
  3. 新 Skill 的最佳位置是 rag-intake 之后、rag-schema/rag-governance 之前。rag-intake 负责用户清单和敏感预检；新 Skill 负责结构保真和产物生成；rag-schema 负责验证；rag-governance 才能处理 RC。
  4. 正式下游只能消费 confirmed_active RC。候选材料可以生成 candidate packet，但必须带 need-review、candidate 或 blocked 状态，不得伪装成正式依据。
  5. 面向下游的包必须把“证据”和“指令”分离。所有文档内容只作为证据，不得覆盖 Agent 工具权限、审批规则、目标或安全边界。

Conflicts And Uncertainty

问题处理剩余限制
外部 RAG 框架支持 metadata，但不定义本项目 RC 状态。用本地 rag-governance 作为权威边界。属于本地政策，不是公开标准。
PROV 模型比本地 MVP 复杂。只映射最小字段：entity/source、activity/intake、agent/user-or-skill、locator。后续如要审计更细，可扩展。
SQLite/向量检索有工程价值，但会引入派生索引一致性问题。保持 INDEX.md + frontmatter + manifest + evidence JSON 为 MVP 真值；FTS5/向量只做可重建缓存。需要阈值和重建校验。

Main Workflow Recommendation

  1. 将新 Skill 命名为 rag-structure-fidelity 或同义名称，挂在 rag-system 下，位置固定为 rag-intake 后、rag-schema/rag-governance 前。
  2. 第一版硬性交付 structured Markdown + frontmatter + evidence JSON + admission/reject report，并强烈建议同步生成 structure map JSON 和 validation report，否则下游很难稳定消费。
  3. 下游 handoff 不直接读取结构化正文，而是消费 Evidence Packet、RC Packet、Change Impact Packet、Test Asset Manifest、UI Test Packet 或 Solution D Evidence Contract。
  4. 任何正式用例、UI 自动化、Solution D 结论都必须由 confirmed_active RC 或用户明确授权支撑；候选材料只能生成带 need-review 的候选包。
  5. 下一步进入 grill-system 时，重点确认：是否把 structure map JSON 和 validation report 也设为第一版硬门槛。
