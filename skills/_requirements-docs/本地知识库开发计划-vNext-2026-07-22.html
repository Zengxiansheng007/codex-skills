本地知识库开发计划 vNext

documentType：Development Plan

目标：以本地文件和结构化元数据为源真值，分阶段实现 D:\RAG 知识库 MVP；本计划不执行部署，只定义开发任务、接口、门禁和验收。

源基线：本地知识库 PRD vNext、WorkBuddy PRD v1.1、Codex 历史 PRD、本轮 research 与 Grill。

1. 开发原则

  • 先结构治理，后检索优化：MVP 先完成 schema、目录、准入、证据、RC、查询契约。
  • 文件为源真值，索引为派生物：MVP 先使用 INDEX.md、frontmatter、manifest 和证据 JSON；08_cache 可删除重建，不承载唯一事实。
  • 只处理用户显式提供材料：不自动扫描其他磁盘目录。
  • confirmed_active 是正式 RC 前置条件；active 只代表待审池。
  • 下游 Skill 只读接入：本阶段预留接口，不执行 ui-test、auto-testcase-generator、Solution D。

4. Q6 展开：SQLite FTS5 与缓存层怎么判断是否引入

已确认方案：MVP 先使用 INDEX.md、frontmatter、manifest 和证据 JSON；当语料规模、黄金查询失败率或人工查找成本达到阈值后，再引入 SQLite FTS5；向量索引放在更后阶段。SQLite FTS5 适合作为本地全文检索后端，但不应在 MVP 一开始就成为硬依赖。原因是当前最关键风险不是检索速度，而是事实治理：是否只读用户提供材料、是否防敏感、是否区分 active 和 confirmed_active、是否可追溯。

小白版理解：可以把本地知识库想成一个“资料柜 + 目录卡 + 搜索机”。01_raw/02_structured/03_evidence/06_governance 是资料柜和目录卡，里面放的是可追溯的原文、证据、状态和用户确认；08_cache 像一台搜索机，只是帮你找得快。搜索机坏了可以重建，不能把搜索机里的结果当成事实本身。

为什么不一开始就上 SQLite 或向量库：早期最容易出大错的不是“搜得慢”，而是“搜到的东西能不能用”。如果材料还没确认、RC 还没裁决、敏感信息还没挡住，检索越快只会越快地把错误传播给下游 Agent。因此 MVP 先把资料柜、目录卡和人工确认规则做好；等资料变多、查询变慢、黄金查询证明需要更强检索时，再把 SQLite FTS5 接到 08_cache。向量索引更适合后续语义召回 POC，不进入 MVP。

方案优点缺点建议
纯文件 + INDEX/frontmatter + manifest + 证据 JSON简单、可审计、易迁移、无额外依赖，最适合先把事实治理做稳语料大后查询慢；复杂组合查询不舒服MVP 确认采用
SQLite FTS5 / 08_cache本地、成熟、支持 BM25、可重建、适合结构过滤中文分词、索引更新、重建一致性需要验证PH-6 POC 后引入
向量索引语义召回强，适合同义表达和长文本可解释性弱、误召回、嵌入泄露与版本重建复杂后续 POC；不得作为事实源

阈值策略：是否引入 SQLite FTS5 不靠拍脑袋，而看三类信号：语料规模是否明显增长、黄金查询失败率是否暴露纯文件检索不足、人工查找成本是否已经影响效率。具体数值需要首批语料和黄金查询跑出基线后再定；达到阈值前继续使用 INDEX.md、frontmatter、manifest 和证据 JSON。向量索引需另行审批，且放在 SQLite FTS5 之后。

高置信参考支撑：该方案有官方资料支撑。SQLite FTS5 官方文档说明 FTS5 支持本地全文检索、BM25 排序、tokenizer、integrity-check、rebuild 和外部内容表；这些能力支持把 SQLite 作为本地 08_cache。同一官方文档也说明外部内容索引需要维护一致性，因此它不应成为唯一事实源。OWASP LLM Top 10 与 OWASP AI Agent Security Cheat Sheet 支撑“检索命中不是事实、Agent 需要最小权限和人工审批”的安全边界。

7. 风险与回退

风险影响缓解
用户未提供首批材料无法真实建库验收仅完成空库骨架和样例夹具，不导入真实内容。
材料含敏感信息泄露或污染知识库拒绝该项，不复制敏感正文，只记录拒绝原因。
active 被误用未确认事实进入正式用例语义校验和下游契约都要求 confirmed_active。
SQLite/向量过早引入复杂度上升、事实源混乱PH-6 后置 POC；索引不得成为事实源。
内部 Skill 格式未知下游集成返工先定义稳定最小契约，真实接口待用户提供后适配。
