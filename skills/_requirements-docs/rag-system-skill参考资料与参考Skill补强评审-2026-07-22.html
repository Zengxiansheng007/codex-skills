rag-system Skill 参考资料与参考 Skill 补强评审

报告 ID：RES-RAG-SYSTEM-SKILL-20260722

问题：针对“本地数据库 + rag-system 根 Skill + 可拆分子 Skill”的开发计划，检索参考资料与参考 Skill，评审是否存在缺陷/优化点，并持续补漏到无 P0/P1 证据缺陷。

边界：未安装或执行第三方 Skill/框架，未创建 D:\RAG，未创建 .codex/skills/rag-system。

1. 总结

结论为 accepted-with-optimizations：当前“rag-system 根协调 Skill + 子 Skill + 本地文件/证据数据库”的方向成立。补强后，无未关闭 P0/P1 证据缺陷；仍保留 P2 级优化项：后续创建真实 Skill 时应补结构校验脚本、真实 forward-test、下游接口样例和黄金查询审批记录。

核心优化是避免把 rag-system 做成一个巨型 Skill。参考 Open Agent Skills、OpenAI Skills 与 GitHub Copilot Skills 后，推荐 rag-system 只做路由、门禁、上下文加载和结果聚合；摄取、schema、治理、查询、变更影响、下游交接、评测、缓存等能力拆成子 Skill。

S13DeepEval Agent Evaluation / Faithfulness支持端到端与组件级 agent/RAG 评测、trace、faithfulness。部分指标由 LLM-as-a-judge 驱动。作为后续 rag-eval 参考，不阻塞 MVP。

4. 缺陷补漏迭代

轮次发现的缺陷/优化点补充资料/Skill处置后剩余 P0/P1
R1rag-system 有变成巨型 Skill 的 P1 风险。Open Agent Skills、OpenAI skill-creator、本地 create-agent-skill rubric。0。改为根协调 + 子 Skill。
R2RAG 框架资料偏向向量/召回，可能弱化 RC 治理。LangChain、LlamaIndex、SQLite FTS5、JSON Schema、W3C PROV-O。0。采用“文件/证据真值 + 检索缓存派生”。
R3Agent 读取文档后可能受提示注入、过度自治或工具误用影响。OWASP AI Agent、OWASP LLM Top 10、MCP Tools Spec。0。检索内容只作数据；写入、RC、跨环境、Skill 创建均需审批。
R4下游测试用例/UI 自动化需要稳定契约，否则 rag-system 会越权执行。本地 auto-testcase-generator、ui-test、Promptfoo、DeepEval。0。只输出只读 Contract，不执行下游。
R5评测资料中 LLM judge 不确定，不能做 P0/P1 验收主依据。Promptfoo RAG eval、DeepEval faithfulness、LlamaIndex evaluation。0。LLM judge 降级为 P2 POC；主验收用用户审批 golden query + 确定性 schema/状态/隔离测试。

5. 对开发计划的优化建议

  1. 保留当前根协调架构：rag-system 只负责路由、门禁、上下文加载、结果聚合；不要承载全部细节。
  2. MVP 子 Skill 缩到 6 个：rag-intake、rag-schema、rag-governance、rag-query、rag-change-impact、rag-downstream-handoff。rag-eval 和 rag-cache 后置。
  3. 为每个子 Skill 定义最小契约：输入、输出、拒绝条件、证据、验证命令，不提前写成长教程。
  4. 新增统一 envelope：所有下游包统一带 knowledge_space_id、sourceBaseline、requires_status、evidence_refs、blocked_reason。
  5. 新增 Skill 创建门禁：真实写入 .codex/skills 前必须再次确认，并运行结构校验、敏感扫描和 forward-test。

6. 最终评审

结论：无未关闭 P0/P1 缺陷。当前开发计划可作为 rag-system Skill 设计输入，但不能直接视为执行授权。

仍需用户确认：是否允许后续创建真实 .codex/skills/rag-system 及子 Skill 目录；首个 knowledge_space_id 具体值；首批材料清单；下游真实接口样例。
