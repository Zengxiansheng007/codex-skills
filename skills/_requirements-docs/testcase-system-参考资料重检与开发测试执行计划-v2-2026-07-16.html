testcase-system 参考资料重检与开发测试执行计划

报告 ID：RES-TS-SKILLS-002｜版本：v2.0｜日期：2026-07-16｜深度：standard｜状态：complete｜建议：accepted-with-constraints

结论：已确认的九 Skill 架构与原 v2 需求方向一致，但此前计划缺少四类实现级证据：宿主是否支持多 Skill 协作、跨 Skill 契约如何传递、Skill 触发冲突如何测试、Agent 行为如何形成可重复回归。新版计划采用“宿主兼容性探针 → 契约优先 → 单 Skill 纵向实现 → 跨 Skill 合同测试 → 离线 forward-test → 安全与评估门禁”的顺序。P0/P1 不安装 Promptfoo、DeepEval、Pact 或其他大型框架；先用 JSON Schema、确定性脚本和合成夹具建立基线，再决定是否做隔离 POC。

1. 范围与依据

需求基线《测试用例编写完整流程与需求文档 v2》以及已确认的《testcase-system 多 Skill 体系需求基线 v1.0》。
体系边界九个 Skill：主编排、来源治理、需求挖掘、Grill、领域建模、测试设计、输出治理、变更反馈，以及独立下游 ui-test。
确认决策DR-TS-001 至 DR-TS-004：九 Skill 分工；编排器无业务事实写权；单一版本化共享契约；P0/P1 仅合成/脱敏材料。
本轮包含参考资料刷新、缺陷评审、证据缺口修复、开发工作包、测试矩阵、forward-test、门禁和交付顺序。
本轮不包含不创建 Skill 包、不部署 RAG、不安装第三方框架、不访问真实系统、不扫描磁盘、不使用账号或生产数据、不修改原始需求文档。

2. 更新后的关键发现

发现证据对方案的影响
Agent Skills 规范只定义单 Skill 包和渐进加载，不定义跨 Skill 编排协议规范定义 SKILL.md、scripts/、references/、assets/，并以 metadata、instructions、resources 三层渐进加载；规范页面未定义 orchestration 或 skill-to-skill invocation。Agent Skills Specification先做宿主兼容性探针；跨 Skill 协作必须由本项目的 Run Manifest/Handoff Contract 明确定义，并提供缺少 Skill 或宿主不支持组合时的阻断降级。
公开规范与本地运行时的 frontmatter 规则存在差异公开规范允许若干可选 frontmatter 字段，且 allowed-tools 标为实验性；本地 create-agent-skill 约束只保留 name 和 description。以本地运行时规则为准；不在 frontmatter 使用版本、权限或依赖扩展字段。版本与权限写入共享契约和正文，并用本地 validator 验证。
共享契约适合用 JSON Schema 做结构验证，但 Schema 不能证明语义和权限JSON Schema Draft 2020-12 定义结构断言、组合和验证输出；format 是否作为断言取决于方言配置。JSON Schema 2020-12、Validation VocabularySchema 负责字段、枚举和结构；另写确定性语义校验器验证 RC 权限、Scope、状态迁移、断链、循环、P0 阻断和 formal 条件。禁止把“Schema valid”当成“业务有效”。
跨阶段必须保留双向追溯、孤立项和变更影响NASA SWE-052 要求需求、设计、验证和不符合项之间的双向追溯，并要求可验证的客观证据；SWE-053 要求变更在实施前分析对系统、接口、测试、风险和进度的影响。SWE-052、SWE-053每个 Skill 都不能仅检查自己的输出；必须执行 producer/consumer 链路测试。变更先生成 CHG/IMP 候选，不自动修改 RC 或 formal TC。
统一测试模型可提升一致性，但会遗漏模型外条件ISTQB CTAL-TA v4.0 要求测试条件追溯到测试依据，讨论测试预言机、数据和环境；同时提醒自动化模型可能遗漏模型之外的测试条件并低估维护成本。ISTQB CTAL-TA v4.0TC Model 作为唯一渲染源，但加入“模型外探索项”和人工抽样；预言机、环境、数据、清理和证据入口是 TP/TC 的必填设计项。
Agent 需要独立、可重复和对抗性的测试NIST 建议在生成式 AI 生命周期早期迭代并记录 TEVV；OWASP 要求最小权限、结构化输出、人工批准、注入/记忆污染/工具滥用回归及版本化拒绝样本。NIST AI 600-1、OWASP AI Agent Security每个 Skill 必须有正向触发、负向触发、权限拒绝、注入拒绝和输出契约测试；高风险门禁用确定性断言，不依赖 LLM 自评。
评估框架可补充但不能代替业务预言机DeepEval 的 Tool Correctness 核心可对实际/期望工具调用做确定性比对，但“最优工具”仍可使用 LLM 判断；Promptfoo 支持回归、红队和 CI 门禁，但可能需要 Node、模型和 API Key。DeepEval Tool Correctness、Promptfoo CI/CDP0/P1 先使用自有黄金夹具和确定性验证。第三方评估只作为后续 POC，模型评分不得确认 RC、关系或业务成功。
UI 执行证据必须分层Playwright 可捕获网络响应并通过 Trace 查看动作、DOM 和网络；页面证据仍不等于下游业务成功。Playwright Network、Playwright Best Practicesui-test 交接必须注明 UI、API、异步任务、下游和恢复预言机；本体系只定义 Execution Contract，不在 P0/P1 执行真实 UI。

3. 参考资料缺陷与优化点

参考资料可采用内容缺陷/不适用点本项目优化
Agent Skills 规范目录结构、触发描述、渐进加载、相对资源引用、结构校验。没有跨 Skill 调用、事务、共享状态、重试、幂等、审批或产物版本协议；实验性权限字段跨宿主不稳定。新增 Host Capability Report、Run Manifest、Handoff Contract、idempotency key 和明确的 blocked/fallback 状态；以本地 frontmatter 规则优先。
JSON Schema 2020-12统一对象结构、枚举、条件、输出和 schema version。只能验证结构，不能判断引用存在、用户是否真正确认、Scope 是否适用或链路是否完整；不同 validator 对 format 支持可能不同。Schema + semantic validator 双门禁；固定方言 URI 和 validator 版本；用无效夹具验证错误定位。
NASA SWE-052/053双向追溯、孤立项、客观证据、变更影响和审批前分析。高保证工程背景较重，不能机械套用安全关键覆盖率、组织角色和成本控制方式。保留方法，不复制 NASA 合规结论；按 RC 风险分层，P0 逐项门禁，其他指标由试点基线校准。
W3C PROV-OEntity/Activity/Agent、派生、修订、失效和责任主体。语义丰富，直接完整实现会增加上下文和数据复杂度。只映射最小子集：实体、活动、责任主体、派生、修订、失效；不在 P0 引入 RDF 或图数据库。
ISTQB CTAL-TA测试依据、风险、预言机、环境、数据、模型化设计和回归影响。面向测试分析角色，不定义 LLM 来源治理、RC 权限或多 Skill 合同。把其测试设计方法放进 testcase-designer，由治理 Skill 提供来源/裁决前置门禁。
NIST/OWASPTEVV、最小权限、人工监督、输入/输出验证、红队与证据保留。原则范围广，不提供 testcase-system 的具体门禁字段和阈值。转化为可执行拒绝夹具、权限矩阵、链深/重试上限和发布证据清单；阈值由合成基线确认。
Promptfoo/DeepEval批量回归、工具调用比对、红队、CI 输出。引入依赖、模型调用、密钥、成本和评分偏差；README/文档主张需要本地复现。列为 P2 可选 POC；P0/P1 不安装。先建立可被任何框架读取的 JSON 黄金集和结果格式。
Pact 合同测试消费者定义期望、提供者端验证的思想。主要针对服务 API；本体系以文件/产物交接为主，引入 Pact 过重。采用 consumer fixture + JSON Schema + semantic validator 的轻量合同测试，不引入 Pact 运行时。
Playwright网络等待、可重试断言、Trace 和浏览器证据。仅覆盖浏览器执行层，无法替代规则、异步任务和下游验证。仅用于 ui-test 下游；Execution Contract 强制声明非 UI 预言机和业务 ID。

4. 补齐后的目标架构

核心设计：九 Skill 保持已确认边界，但共享契约由 testcase-system 持有并通过每次运行的 contract_bundle_ref 传递。下游 Skill 不跨目录读取另一个 Skill 的资源，也不复制核心 Schema；若缺少契约、版本不兼容或宿主无法加载所需 Skill，必须返回 blocked。
用户请求
  -> testcase-system: Host Probe + Run Manifest + contract_bundle_ref
  -> 专职 Skill: 消费上游 artifact，产生下游 artifact + validation report
  -> testcase-system: Gate 检查 + Handoff
  -> ui-test（可选下游）
  -> testcase-change-feedback

每段交接必须包含：run_id、contract_version、producer_skill、producer_version、
artifact_type、artifact_ids、scope、source_hashes、status、issues、next_gate。
新增契约作用硬门禁
Host Capability Report记录宿主能否发现、加载多个 Skill、读取资源和运行脚本。缺少必需能力时停止，不假装已调用下游 Skill。
Run Manifest绑定 run、用户目标、Scope、来源授权、契约版本和阶段状态。无 project_id/product_id/knowledge_space_id/environment 不进入 G1。
Shared Contract Bundle包含 JSON Schema、状态机、关系白名单、预言机枚举、错误码。producer/consumer 版本不兼容即 blocked；迁移必须显式登记。
Handoff Contract每阶段的输入、输出、问题、证据和下一门禁。无 producer、hash、artifact IDs 或 validation result 不接收。
Evaluation Record记录 Skill/模型/工具策略、夹具、结果、成本和人工裁决。高风险负向测试失败不得发布；LLM 分数不能覆盖确定性失败。

5. 详细开发与测试计划

阶段 S0：冻结基线与建立实施工作区

开发步骤1）锁定需求基线 v2 和 DR-TS-001~004；2）建立 Skill 清单与 ownership；3）为九 Skill 分配唯一写对象；4）定义 P0/P1 excluded scope；5）把现有 Python 原型登记为“可拆取脚本原型”，不作为产品入口。
测试步骤1）核对 FR-TCD-001~012、BR、NFR 均有负责 Skill；2）检查不存在两个 Skill 对 RC/formal TC 的竞争写权；3）构造“直接调用专职 Skill 且无 Run Manifest”的负向场景，应返回 blocked。
产物skill-inventory.json、ownership-matrix.md、scope-boundary.md、需求到 Skill 的 RTM。
退出门禁FR/BR/NFR 映射完整；写权限无冲突；用户确认规则未被转交给 Agent。

阶段 S1：宿主兼容性探针与编排降级

开发步骤1）定义需要的宿主能力：Skill 发现、完整读取、资源读取、脚本运行、多 Skill 顺序使用；2）编写只读 capability probe；3）输出 Host Capability Report；4）在 testcase-system 中定义 missing-skill、unsupported-composition、script-unavailable 三类阻断；5）禁止静默退回“单 Agent 自己完成所有角色”。
测试步骤1）全部能力可用；2）缺少某专职 Skill；3）不能运行脚本；4）同名 Skill 冲突；5）宿主只支持单 Skill。逐项验证报告和降级路径，不执行业务阶段。
产物host-capability.schema.json、probe 脚本、5 个宿主夹具、阻断错误码。
退出门禁任何能力缺失都有可解释状态；测试证明不会虚构下游调用结果。

阶段 S2：共享契约 v1 与语义验证器

开发步骤1）固定 JSON Schema Draft 2020-12；2）定义 SRC/EVD/CLM/ISS/RC/MOD/OBJ/STATE/TP/TC/CHG/IMP/RUN/RCA；3）定义 Run Manifest/Handoff/Evaluation Record；4）定义状态机、关系白名单、Scope 和预言机枚举；5）实现 semantic validator：引用存在、类型匹配、RC 用户确认、P0 阻断、孤立项、循环、formal 条件；6）实现显式 migration registry。
测试步骤1）每个 Schema 的最小有效/缺字段/错枚举/多余字段夹具；2）format assertion 配置测试；3）跨引用断链；4）Agent 伪造 confirmed_by；5）非法状态跳转；6）未知迁移版本；7）循环追溯；8）formal TC 无 RC/P0 开放。
产物共享 Contract Bundle v1、schema validator、semantic validator、migration registry、错误码目录和无效夹具。
退出门禁结构与语义错误都能定位到对象 ID、字段和 Gate；未知版本明确拒绝，不按同名字段猜迁移。

阶段 S3：主编排 Skill 与来源治理 Skill

开发步骤1）创建精简的 testcase-system/SKILL.md，description 覆盖完整流程触发词；2）只保留编排、门禁、资源路由和失败路径；3）创建 testcase-source-governance；4）实现用户显式来源清单、hash、分类、定位、SRC/EVD/CLM 和 Evidence Packet；5）禁止磁盘扫描与检索命中自动升格。
测试步骤触发测试：完整用例任务应触发 orchestrator；单纯概念问答不触发。来源测试：用户指定合成文件通过；Agent 自选目录、敏感扩展名、疑似凭据、过期/冲突来源被拒绝或标记；Evidence Packet 验证 unknown/conflict/need-review/resolved。
产物两个 Skill 包、source manifest 模板、Evidence Packet 模板、准入/检索脚本、正负触发集。
退出门禁Skill 结构校验通过；每条 CLM 可回到 EVD/SRC；无授权来源不会进入下游。

阶段 S4：适配 prd-test-miner 与 grill-system

开发步骤1）审计现有两个 Skill 的 trigger、输入和输出；2）添加 Contract Bundle/Run Manifest 前置要求；3）miner 输出模块、对象、角色、状态、规则、数据、接口、异步、下游和 unknown；4）Grill 生成带 severity、blocked_objects、root_question 和 closure_evidence 的 ISS；5）记录用户回答，但 candidate RC 必须经独立 user confirmation action。
测试步骤1）完整/缺失/冲突 PRD；2）PRD 与代码主张冲突；3）用户被 Agent 建议诱导仍未明确确认；4）同一 P0 多轮回答；5）重复根因；6）miner 不输出 formal TC；7）Grill 不按来源固定排名、不自动确认新旧关系。
产物两个适配后的 Skill、Mining Report Schema、ISS/RC 候选交接夹具、Grill forward-test 集。
退出门禁关键 unknown 全部有 ISS；Agent 无法写 confirmed RC；P0 未关闭时编排器停止。

阶段 S5：领域建模与测试设计 Skill

开发步骤1）创建 testcase-domain-modeler，从适用 RC 生成 MOD/OBJ/STATE、权限和上下游关系；2）创建 testcase-designer，生成 TP/candidate TC；3）强制选择预言机、风险、前置、数据、步骤、逐步预期、清理/恢复和证据入口；4）自动化候选只给出评估，不生成 UI 脚本；5）模型外探索项单独登记。
测试步骤1）无 RC 建模；2）跨 project/product Scope 污染；3）非法状态迁移；4）权限负向；5）边界、组合、异步、恢复场景；6）UI 预言机被误用于下游业务；7）模型外风险缺失；8）candidate/formal 隔离。
产物两个 Skill、domain/test-case 模板、oracle catalog、设计覆盖报告、模型外探索清单。
退出门禁每个关键 RC 至少有可观察 TP；formal TC 的链路、Scope、预言机、数据与恢复字段完整。

阶段 S6：输出治理与变更反馈 Skill

开发步骤1）创建 testcase-output-governance，从统一 TC Model 渲染 JSON/Markdown/HTML；2）加入跨格式 canonical comparison；3）创建 testcase-change-feedback，登记新旧来源、语义标签和 CHG/IMP；4）从变化来源沿反向追溯传播到 RC/模型/TP/TC；5）接收合成 RUN/EVD/ISS，按产品/需求/数据/环境/脚本/工具/Agent 分类 RCA；6）同 RCA 第二次触发升级。
测试步骤1）三格式 ID/字段/数量等价；2）HTML 转义和结构；3）文字改写不误判规则变更；4）对象/状态/角色/接口变化命中下游；5）不自动改写 RC/formal TC；6）第二次同根因升级；7）删除或弱化高风险用例被拒绝。
产物两个 Skill、renderer、canonical comparator、impact walker、RCA classifier、回归包模板。
退出门禁三格式零语义差异；影响候选可解释到来源差异和追溯路径；所有变更保持人工处置状态。

阶段 S7：ui-test 交接适配

开发步骤1）不修改 ui-test 的需求解释权；2）定义 Execution Contract：case ID、Scope、入口、选择器线索、业务 ID、预言机类型、网络/任务/下游证据、写风险和清理；3）定义返回 RUN/EVD/ISS；4）页面成功与业务成功分开判定。
测试步骤全部使用合成执行报告：UI 成功/API 失败、API 成功/任务超时、任务成功/下游失败、清理失败、截图缺失、业务 ID 缺失；验证不能错误关闭 TC。
产物Execution Contract、合成 RUN/EVD fixtures、下游交接验证器。
退出门禁每个 pass/fail 结论都能匹配对应预言机；UI 证据不会越权证明非 UI 结果。

阶段 S8：多 Skill 协作 forward-test 与发布门禁

开发步骤1）建立版本化黄金集与拒绝集；2）记录 Skill 版本、契约版本、宿主、模型、工具策略和输出 hash；3）构造 end-to-end Run Manifest；4）执行九 Skill 顺序协作；5）生成 RTM、Gate Report、差异报告和残余风险。
测试步骤执行下述 FWT-001~012；分别跑单 Skill、producer/consumer、全链路和变更回归。确定性失败优先于模型评分；人工对候选 RC、模型外项和高风险 TC 抽样。
产物golden-set v1、denial-set v1、12 个 forward-test、Evaluation Record、Release Gate Report。
退出门禁所有硬门禁通过；无未解释的黄金集退化；安全拒绝全过；输出可由另一 Agent 复核。

8. 发布门禁与指标

硬门禁

  • 九 Skill 均通过本地结构校验；触发描述有正向和负向样本。
  • 所有 artifact 通过固定方言的 Schema 和 semantic validator。
  • formal TC 到 RC/EVD/SRC 的关键链路完整率为 100%，无断链、循环或未处置孤立项。
  • 无未关闭 P0；无 Agent 确认 RC；无自动确认新旧关系；无跨 Scope 污染。
  • JSON/Markdown/HTML 来自同一模型且 canonical comparison 无语义差异。
  • 安全拒绝集全部通过，日志和夹具无真实凭据或生产数据。
  • 宿主或 Skill 缺失时明确 blocked，不生成伪造的下游产物。

趋势指标

追溯缺口、影响分析误报/漏报、触发准确率、人工复核一致率、候选转 RC 比率、模型外测试条件发现数、重复 RCA、单阶段耗时和上下文成本。趋势阈值在合成基线和首个受控试点后由用户确认，不在设计阶段虚构固定百分比。

10. 风险、冲突与不确定性

  • 多 Skill 可移植性：公开规范没有跨 Skill 编排标准。本计划的 Run Manifest/Handoff Contract 是项目层协议；换宿主时必须重跑 S1。
  • frontmatter 差异：公开规范允许可选字段，本地运行时更严格。当前实现必须服从本地规则，不能以公开规范“允许”作为本地可用证明。
  • 共享契约位置：下游 Skill 不应跨目录硬编码读取 orchestrator 资源。契约通过运行输入引用和 hash 传递；独立调用缺少契约即 blocked。
  • 评估偏差：LLM judge、工具最优性评分和红队生成会受模型、提示和提供商影响；只作为补充证据，不能覆盖 deterministic gate。
  • 高保证标准比例：NASA 方法用于追溯和变更治理，不宣称本项目达到 NASA 或任何 ISO 合规。
  • 真实项目适用性：P0/P1 只证明合成/脱敏样本上的体系正确性；真实项目仍需用户确认 Scope、资料和环境后单独试点。
