## Summary

Implement CLW-ST-101: Story Profile definition, single-Story live handoff gate, and Large Story splitting requirement. A live handoff must identify exactly one Story; Small and Medium profiles are executable; Large must fail with a split-required finding before execution.

## Context And Problem

The Claude Windows Adaptive Loop requirement anchor (CLW-ADAPTIVE-LOOP-REQ-20260816-001@1.0.0) requires that each Claude live invocation executes exactly one Story, and that Large Stories must be split into Small or Medium Stories before execution. PH-1 through PH-4 established the development-system governance runtime, but no Story Profile, single-Story gate, or splitting gate existed.

## Decision And Alternatives

Selected a strict pre-live Story envelope and explicit Large split finding. Rejected prompt-only enforcement, silently selecting the first Story from a multi-Story packet, and assigning executable budgets to an unsplit Large Story.

- All existing tests preserved without weakened assertions

- Negative fixtures generated by `development_runtime.py generate-clw-st101-fixtures`

- Story Profile deadlines respect the ordering: initial < no-progress <= hard <= total
- maxRounds is bounded to [1, 10]
- No global Skill writes or user-level installation
- No network access or dependency installation

## Codex Takeover Review

The Claude Attempt reached the 900-second hard deadline after producing code but before final feedback. Codex used the single preauthorized same-Story takeover. Review found and repaired one P1 requirement drift: the generated timeout defaults did not match Q-012, and the Large profile incorrectly carried a larger execution budget. The validated defaults are Small 15/10/20/45/90 minutes with 2 rounds and Medium 30/15/30/90/240 minutes with 3 rounds; Large carries only `splitRequired=true`. Schema gates now also enforce exactly one Story.

## Safety And Privacy

The change is limited to the approved workspace copy. It does not install a Skill, invoke a new live Agent, read credentials, use production data, or expand an existing permission boundary.

## Risks And Follow-up

The deterministic single-Story gate is validated, but CLW-PH-1 live completion remains dependent on a valid provider response and Codex CompletionEvaluator evidence. Later PH-2 queue orchestration must keep this envelope unchanged.
