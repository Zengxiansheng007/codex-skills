# writer / runner 联合测试方案 v0.1

日期：2026-10-14。测试边界已由本轮用户确认；**下列产品案例当前全部 not-run**。本轮只核文档，不执行真实接口、JMeter、Java控制或WorkBuddy。

## 1. 验证原则与先例

主要边界为 writer 编写→逐目标验证→交付、runner 接收→正式执行，以及报告监控通知/续建/用户控制公开入口。验证对外产物、调用/实际样本数、启用集合、差异、状态和范围，不依赖内部函数如何拆分。controller 保留一个可注入的阶段执行适配器；可控时钟只用于时间逻辑，不能替代真实600秒窗口。

复用现有 runner tests/test_controller.py 的可注入执行器/版本探针、合成报告/JTL、串行/无重发、hash保留；test_jmx.py 的独立结构差异比较；test_entry.py/test_workbuddy_bridge.py 的真实结果绑定；test_report.py/test_search.py 的官方指标/固定算法边界。以 B 为开发起点时同步保留 Word/附录的测试预期，不直接运行 A 中只接受 Markdown 的断言证明 B。

每次开发只验证新增及直接关联模块。完整方案列出最终覆盖集合，不要求每轮重跑所有案例。实际案例结论使用 planned/not-run/passed/failed/inconclusive/not-tested，必须附命令/输入、实际范围、观察和证据；pass数量、exit0、hash或原型不代替AC。

夹具服务以健康检查和所有授权进程实际结束为生命周期边界，不能用过短600秒自结束制造连接拒绝。服务监听/日志、JTL、进程和时间线共同判断错误；无材料不能归因。每项原则上一次受控执行，失败先固定事实与根因，再按具体范围决定补验，不自动追加负载。

**长等待和停止夹具说明**：正常小报告可能很快退出，不能可靠触发600秒，也不能在原Java已经退出后用Python sleep/假running冒充。J-11/12、H-07/08需要专用、可核对真实report Java仍存活的等待夹具；技术候选是后续单独授权的本地JDK启动等待/暂停注入，只限该轮测试，不修改发行JMX、用户JMeter全局配置或产品超时策略。先记录准确注入方法、实际Java状态及测试环境差异，再执行。没有可接受夹具或没有自然长报告时，保留对应not-tested/inconclusive，不能拿缩时模拟关闭G-04/05的实证部分；可先完成独立-g正常链与其他离线覆盖。

H-07即使观察成功也不证明正常报告会卡死；受控等待夹具的差异必须写出。用户实时回复可能晚于短窗口，需测试前明确停止策略；不能把“提示→用户回复→停止”多次错过窗口写成通过。
