## 评审时优先看这五项

1. writer 仍只写脚本、按业务 **1 线程 / Ramp-up 0 / 持续 1 秒**短验证；runner 独立确认正式任务并寻峰。
2. runner 强制准备目录；每轮严格“采样退出→独立官方报告退出并核验→评分”，目标 TPS/P90/错误率仍来自官方 report。
3. 自动认证契约由 writer 生成，runner 只消费；认证先核验，失败不进入评分。本轮已完成 JTL 仍保留并走独立报告步骤，不能绕过报告等待规则。
4. 主后台与监控后台分开；报告满 600 秒仅一次提醒，WorkBuddy 先续建再分析/提问。停止由用户决定，主程序核实原报告退出后才去下一 HTTP。
5. Windows 报告进程归属、原生认证/CSV、600 秒通知与续建都是**待实测资格门**。方案明确不等于已可用，历史停止整棵主任务的证据不能替代报告专用停止。
