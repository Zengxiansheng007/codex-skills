# 联合规格术语

本表对齐 [writer 术语](../baselines/writer/GLOSSARY.md) 与 [runner 术语](../baselines/runner/GLOSSARY.md)，不改写原文。

| 术语 | 联合语义与边界 |
|---|---|
| 联合开发计划 | 两个 Skill 的接口、依赖与验收在同一计划管理；不是合成一个产品入口或新增执行台账。 |
| 正式原件 | writer 交付或工程师提供的 JMX；runner 重新确认后消费。不是 writer 1 秒验证副本。 |
| 预登录 | 为获取缺失 JSON Cookie 提取依据的一次受控请求，和随后 JMX 验证分别计数。 |
| 认证准备 | JMeter setUp 阶段生成本轮 Cookie；正式按全部配置账号准备，writer 短验证只用一个账号。 |
| 生成依赖 | 本轮 JMeter 固定构件生成、由限定消费者读取的文件；未生成前不冒充已有静态输入。 |
| 原生 CSV 分配 | CSVDataSet 按迭代读取和回收；不是永久线程→账号绑定，也不自动延长 Cookie 有效期。 |
| 短验证 / 1/0/1 | 业务线程数 1、Ramp-up 0 秒、调度持续 1 秒；并非单样本或整个命令 1 秒内结束。 |
| 验证副本契约 | writer 为短验证允许修改的精准字段与单账号认证 CSV 引用；独立于 runner 正式白名单。 |
| 正式副本契约 | runner 仅改当前业务组并发和 HTTP enabled；认证脚本/账号规模/路径、Ramp-up/时长及业务内容保持。 |
| 消费者接收 | 指定实际 runner 对当前原件/契约/布局的检查；不等于真实执行通过或正式发压许可。 |
| 压测轮次 | 一个目标在一个选定并发下实际启动的采样及结果处理；报告、提醒、控制和续建不增加轮数。 |
| 阶段身份 | 单次 sampling 或 report 的唯一 ID，绑定 task/run/target/round/源结果；PID 只是其中一个事实。 |
| 报告专用进程范围 | 本轮 report 的 cmd/Java 及其归属；不含主控制器、监控、采样进程或其他轮 Java。 |
| 长等待提醒 | 原报告启动满 600 秒仍未完成的一次事实交接；监控不诊断卡死。 |
| 监控代次 | 同一任务每次真实启动的监控实例；续建增加代次，不重置旧报告计时或提醒状态。 |
| 控制受理 | 原报告停止请求已被记录/主程序接受；不等于原进程已经退出。 |
| 退出待核查 | 原报告退出证据不足，禁止下一请求发压；不能用人为填一个布尔值关闭。 |
| 已测最高合格候选 | 本任务实际核验且满足质量门槛的轮次中 TPS 最高项；受范围和预算约束，不代表绝对容量。 |
| 搜索未完成 | 报告技术失败、停止等使该请求没有完成原定搜索；可以同时存在此前有效合格候选。 |
| 产品验收 / 文档检查 | 前者需要真实适用证据；后者只检查来源、编号、链接与文档一致性，不能替代前者。 |
