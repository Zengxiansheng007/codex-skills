# jmeter-tps-writer 领域术语

用于区分 jmeter-tps-writer 的编写/短验证与 jmeter-tps-runner 的独立正式寻峰。CSV采用JMeter原生分配，不增加自研固定身份模型。

## Language

**认证准备**：业务请求开始前取得可用登录态的准备过程；脚本由writer编写，正式执行由runner启动的JMeter完成。

**预登录**：编写完整脚本前，为取得真实登录响应和Cookie提取依据而进行的一次登录，与完整计划试跑中的认证准备分别记录。

**业务压测计划**：面向待测业务 HTTP 请求的 JMeter 测试计划，用于后续性能测试。

**线程组默认请求头**：请求组共同使用、需要随认证状态等更新的头信息；静态头保留在所属请求。

**单会话共享**：多个业务压测线程使用同一个登录会话的负载模型。
_Avoid_: 将单会话多并发称为多个独立登录用户

**多账号独立会话**：多个账号提供各自登录态的测试模式；不额外保证每个线程固定对应一个账号。

**试跑**：为检查脚本行为而执行的有限测试；结果只覆盖本次环境、输入与实际执行范围。
_Avoid_: 将试跑称为峰值测试或容量验收

**验证副本**：为有限试跑从原件派生的计划，其允许变更由验证契约限定，与正式交接原件分开保留。

**正式负载配置**：由工程师确认、供后续性能压测使用的启动与执行时长等参数，与writer短试跑配置分别保存。
_Avoid_: 将短试跑参数直接视为正式压测参数

**验证时长**：本次目标业务组配置的1秒持续时间；启动、认证准备、在途请求完成和报告处理可使整个验证过程更长。

**消费者兼容检查**：核对 JMX及其依赖是否满足指定 jmeter-tps-runner 输入契约的检查。
_Avoid_: 将 JMeter 启动成功直接称为 runner 准入通过

**验证提醒**：按已确认规则不阻止继续使用的说明事项，不能据此声称相应业务判断已验证。

**合格交接计划**：在实际验证范围内满足当前必需接收条件、可交给runner继续使用的计划。未覆盖范围及验证提醒须如实列出。
