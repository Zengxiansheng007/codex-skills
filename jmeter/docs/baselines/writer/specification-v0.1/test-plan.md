# 测试方案 v0.1

日期：2026-10-13。状态：计划；本轮未运行以下产品测试，没有真实 JMeter / 业务通过结论。

用户已确认：“采用入口行为测试＋受控 JMeter 集成（推荐）”。本方案只覆盖新 writer 与关联 runner 消费链，不以全量复验替代针对性证据。

## 1. 测试边界与先例

| 边界 | 怎么验证 | 为什么采用 |
|---|---|---|
| writer 公开入口 | 给完整任务输入，读取最终 JMX、验证副本、差异、调用次数、JTL/结论；有限执行用可注入的单次执行器 | 验证用户看到的行为，避免用实现函数自己的结果当 oracle。 |
| runner check-input / controller.run | 检查接收返回、实际 HTTP 选集、正式副本变化、认证证据与最终结果 | 复用现有 controller 的 executor / version_probe seam，不另造寻峰测试层。 |
| 受控 JMeter 5.6.3 | 本机 loopback 服务返回确定登录 JSON、Cookie 验证、回显与失败数据；对照请求记录/JTL/原生 report | 原生 setUp、CSV、属性解析、请求头和断言不可由 fake 证明。 |
| WorkBuddy 真宿主 | 实际触发、脚本定位、必要提问、固定命令、结论展示与交接 | Codex 离线产物不能证明 WorkBuddy 的现场效果。 |

当前先例：
- tests/test_controller.py：合成报告/JTL、可注入执行器、串行多目标、6 轮、技术错误不重发、问题队列、源 hash 保留。
- tests/test_jmx.py：结构身份、前置关系、正式副本与越权变更拒绝。
- tests/test_entry.py / test_workbuddy_bridge.py：入口与宿主边界、实际目标绑定与状态核验。
- tests/test_report.py / test_search.py：官方目标指标与既有决策边界。

这些先例本轮只读，未运行。测试不得照抄生成器的差异清单来证明副本正确，最终有效请求用受控服务的记录作独立证据。

## 5. 真实 JMeter 集成（需要后续执行授权）

运行目标只用本机受控服务，使用合成账号/Cookie，不访问公共 echo / 业务生产系统。授权时明确案例、目标、线程、时长与轮数。下面是测试计划，不是已经获准运行。

| ID | 实测目的 | 计划规模与证据 |
|---|---|---|
| J-01 | 生成请求语义与有效头 | 每目标业务 1 / 0 / 1；服务记录 method/query/正文/静态头/适用 Cookie，对照 JTL |
| J-02 | 自动 setUp → JSON → CSV → 业务 | 一个验证账号，业务 1 / 0 / 1；顺序时间线、登录/目标样本、CSV/marker/实际 Cookie 使用 |
| J-03 | 正式 N 账号与每轮刷新 | 合成 N=3；正式消费者采用合法最低 10 并发、短的明确时长，限定轮次；每轮 3 次登录与新产物，writer 不被正式调用 |
| J-04 | 原生 CSV 回收与单账号隔离 | 快速接口产生多个样本，不能硬规定正好 3；核对所选会话、表头、EOF/共享设置、原始文件 |
| J-05 | 登录失败、缺值、部分准备、无法发布 | 依赖业务请求计数为 0；不回退旧文件；安全失败原因及认证证据，不自动重试 |
| J-06 | 原生断言与既有无断言 | true / false / 缺字段 / 非 JSON；旧无断言记提醒而不改原件 |
| J-07 | 目录/属性与非当前组资格 | 中文/空格路径、不同 cwd、同 plans 目录两个 JMX；合法输出唯一；非当前组不读错误属性/不发无关请求 |
| J-08 | runner 实际官方 report 与技术问题 | 目标官方行、P90/TPS/错误率、General Infos；认证失效不参与评分，后续目标与问题记录按原规则 |

J-03 的具体档位、短时长和最多轮数由执行时固定有限任务配置；不会沿用示例 50/100/200/500 或历史 120 秒。要测试正式消费者，不能将其合法并发要求改为 1；writer 的 1 线程试跑仍独立。

夹具服务须先通过健康检查，并保持到全部授权 JMeter 进程实际结束，再由夹具所有者关闭。不要用过短硬编码生存窗口制造尾部 Connection refused。观察到错误时对照服务日志、JTL、时间线与监听状态；不能凭“600 秒窗口”猜根因。
