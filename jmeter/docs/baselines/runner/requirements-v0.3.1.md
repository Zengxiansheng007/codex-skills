# WorkBuddy 版实施需求

基线为 ../jmeter-workbuddy-planning-20260920/requirements-v0.1.md，补充已确认的 WB-ANCHOR-002 延迟通知变更。本次用户要求依据验证结果调整方案并开发；范围为工作区候选与离线验证。安装、真机压测与第二环境验证仍由人工执行。本文件替代实施时使用的 v0.1；历史文件不改。

## 继承业务规则

用户明确提供本次 JMX、许可、JMeter 和输出目录；原件只读。固定代码只改运行副本并发与 HTTP enabled，其他参数沿用。每轮仅确认前置加当前单 HTTP，逐目标独立串行寻峰。疑似前置须确认。并发是 10 的倍数，当前值仅作起点候选，上限由用户确认。

绝对预设并发候选 50/100/200/500，每任务确认；每目标最多 6 轮。相邻粗测 TPS 下降≥3% 或质量失败转最佳合格候选附近细测，首轮失败结束该目标继续后续。细测两侧中点向下对齐 10，不重复档位、不自动复测。不承诺全局最高 TPS 或 ±20 精度。

峰值评分使用官方目标 HTTP Statistics 的 TPS、P90、错误率、样本及 report 起止时间；默认候选门槛 0.5%、2500ms 每任务确认。审计发现不替代官方指标。全部轮次六列汇总并标合格峰值；无合格值如实说明。
